# MishMash Mesh: idea analysis, similar projects, blockchain, opinion and questions

Date: 2026-11-27 · Status: version 1 (Claude's analysis) · Polish version: PL / MishMash Mesh

---

## 1. Which abbreviation

| Abbreviation | Pros | Cons |
|---|---|---|
| **MMM** | short, easy, nice "M³" logo | **In Poland and Russia "MMM" is the well-known Mavrodi pyramid scheme** (MMM, MMM Global, also active in Poland around 2015). Combined with a token it looks very bad and may attract regulator attention |
| **MMN** | readable ("MishMash Network"), matches the **.network** domain, no bad associations, easy for hashtags and SSIDs (`MMN-abc123`) | less catchy than MMM |
| **MMMN** | full acronym | long, hard to say, looks like a typo |

**Recommendation: MMN** as the technical short name (SSID, packages, protocol: "MMN node", "MMN gateway"), and **MishMash Mesh** in communication. Domains: **mishmashmesh.net** as the main human-facing site, **mishmashmesh.network** for docs, node map and API (or a redirect). Check the "MishMash" trademark at EUIPO and the Polish patent office before launch (companies with that name exist).

## 2. Similar technologies and their design principles

### LoRa mesh (text, low bandwidth, long range)

| Project | Principles | Strengths | Weaknesses |
|---|---|---|---|
| **Meshtastic** | cheap LoRa modules, phone over Bluetooth, every node rebroadcasts (flooding) | huge community, apps, MQTT, map | flooding scales poorly, tens of bytes/s |
| **MeshCore** | clients vs fixed repeaters, path-based routing | scales better, room servers | younger, fewer apps |
| **Reticulum (RNS)** | medium-agnostic network layer: LoRa, WiFi, Ethernet, packet radio, I2P, TCP; addresses are cryptographic keys | closest to your "all media in one" idea | little known outside enthusiasts, no mass-market hardware |

### WiFi mesh (broadband, shorter range)

| Project | Principles | Relevant to MMN |
|---|---|---|
| **Freifunk (DE)** | volunteers flash routers with **Gluon (OpenWrt + B.A.T.M.A.N.)**, open community network | **exactly your "old router + software" model**, tens of thousands of nodes in Germany |
| **Guifi.net (Spain)** | 35k+ nodes, "Wireless Commons" licence, commons model, companies may earn on services | best example of a sustainable economic model without a token |
| **NYC Mesh** | city network, ~USD 20/month donations, rooftop antennas | shows people pay for independent internet |
| **LibreMesh / qMp** | OpenWrt firmware for community networks, auto-configuration | ready-made node "brain" |
| **AREDN** | WiFi on amateur bands, ham IP network | tens of km with directional antennas, but licensed-only and no encryption |
| **Althea** | routers pay each other for forwarding (micropayments, later its own chain) | **closest to your monetisation idea**, live in the US, Latin America, Africa |
| **Commotion Wireless, Serval** | mesh on phones and routers | discontinued; lesson: no sustainable funding |

### Overlay networks and offline apps

| Project | Principles |
|---|---|
| **Yggdrasil, CJDNS** | encrypted IPv6 mesh, address = key, run over any link |
| **Briar** | messenger over Bluetooth, WiFi and Tor, works offline |
| **Bridgefy, Berty** | Bluetooth mesh messengers |
| **Secure Scuttlebutt, Nostr** | serverless social networks, store-and-forward |
| **Winlink, JS8Call** | e-mail and text over HF, link continents without internet |

### Token-based "DePIN" networks (hardware + blockchain)

| Project | Model | What went well / badly |
|---|---|---|
| **Helium** | LoRaWAN hotspots, Proof of Coverage, HNT token; later 5G and mobile | rapid growth (hundreds of thousands of hotspots), but widespread PoC fraud (spoofed locations), little real traffic, token value fell, moved to Solana |
| **World Mobile** | AirNodes in Africa, WMT token | connects unconnected people, revenue sharing |
| **Wayru, Pollen Mobile, Natix** | WiFi/cellular hotspots with rewards | small, still searching for a model |
| **Althea** | payment for actual data forwarded | less speculation, more real service |

## 3. Projects trying to integrate everything in one system

| Project | Media | Gateways | Works without internet | Open source | Incentives | Status |
|---|---|---|---|---|---|---|
| **Reticulum + Sideband/NomadNet** | LoRa, WiFi, Ethernet, packet, HF, I2P, TCP | own bridges, LXMF | **yes** | yes | none | mature |
| **MeshForge / MeshAnchor** | MQTT over Meshtastic, MeshCore, Reticulum | Meshtastic ↔ RNS ↔ MeshCore | partly | yes | none | early |
| **Mesh-Client** | app for Meshtastic, MeshCore, RNS | common UI | yes | yes | none | early |
| **DVSwitch + AllStarLink + Asterisk** | FM/DMR/YSF/D-STAR/P25 radio + VoIP | radio ↔ SIP/phone | locally yes | yes | none | mature |
| **APRS-IS + gateways** | VHF + internet | SMS, e-mail | locally yes | yes | none | mature |
| **Matrix + bridges (mautrix)** | internet / local network | WhatsApp, Signal, Telegram, Meshtastic (mmrelay) | local server yes | yes | none | mature |
| **Winlink** | HF, VHF, telnet | e-mail | **yes** | partly | none | mature |
| **goTenna Pro, Beartooth** | own UHF/VHF radio | app | yes | no | hardware sales | commercial |
| **Helium** | LoRaWAN, 5G, WiFi | internet | no | partly | token | commercial |
| **Althea** | WiFi, fibre | internet | partly | yes | payments | commercial |
| **Freifunk / Guifi** | WiFi, fibre | internet | locally yes | yes | commons | mature |

**Conclusion:** nobody has yet shipped the whole package of "WiFi mesh + LoRa + amateur/CB radio + SMS + messengers + economic incentives" as one product. Every building block exists as open source. MMN's value can be **integration and a simple installer**, not new protocols. The best "backbone" candidates are **Reticulum** (medium-agnostic) or **Yggdrasil + Babel/B.A.T.M.A.N.** for IP traffic.

## 4. Why people build Meshtastic and MeshCore (motivation to carry over)

1. **Cheap and licence-free:** a LoRa module costs EUR 20–50, the 868 MHz ISM band needs no licence.
2. **Independence and preparedness:** power cuts, mobile outages, floods (interest in Poland surged after the 2024 floods).
3. **Technical fun:** nodes on roofs, towers, mountains, solar power, "who has the longest link".
4. **Local community:** city groups, node maps, meet-ups, joint repeater builds.
5. **Privacy:** encryption, no operator, no accounts.
6. **Visible impact:** the map shows your node helps others.
7. **Money is not the motivator:** these communities are largely **sceptical of crypto**. A token may put some of them off.

**For MMN:** motivate with the map and stats ("your node relayed 1,240 messages"), badges, range leaderboards, local groups, an easy installer and real usefulness in a crisis. Treat rewards (if any) as an extra, not the main reason.

## 5. How to build your "old router + small computer" model

### What works and what needs adjusting

| Part of your idea | Assessment | Proposal |
|---|---|---|
| Old router + Raspberry Pi over Ethernet | good starting point | Stock router firmware has no common API and no mesh mode; the Pi cannot configure every router. **Better:** router in **AP/bridge** mode (just broadcasts WiFi) and the Pi does the mesh with a **second USB WiFi adapter in 802.11s/ad-hoc mode** (e.g. MediaTek MT7612U). Or, if the router is supported, **flash OpenWrt** and skip the Pi |
| Cheaper computer than a Pi | yes | Orange Pi Zero 3, Radxa Zero, an old laptop, or an OpenWrt router (a GL.iNet for EUR 25–50 does it all) |
| Range of tens to hundreds of metres | realistic | 30–100 m in cities. **Several to tens of km** only with directional antennas (Ubiquiti, MikroTik) on rooftop point-to-point links |
| Publishing WiFi credentials on the site | ok, but | Instead of passwords: **open `MMN-xxxx` SSID + encryption at a higher layer** (Reticulum/Yggdrasil/WireGuard). Nodes authenticate with keys, not WiFi passwords |
| Authorisation from MMN servers | caution | If authorisation needs a central server, the network **stops working without internet**. Use distributed authorisation: certificates signed offline, web of trust, local node list |
| A global network of millions of routers | the hardest part | WiFi mesh loses throughput with each hop (roughly halved per hop on a single radio). Cities can be connected, **continents cannot**: you need long-haul links (HF, satellites, community fibre). Without the internet the network will be **a set of islands** joined by slow, text-only links |
| Gateways Meshtastic ↔ MeshCore ↔ SMS ↔ FM/CB ↔ messengers | realistic | Most blocks exist (section 3). CB voice ↔ WhatsApp: a CB radio gateway, Asterisk/DVSwitch, a Matrix bridge or Zello. Mind the law (section 7) |

### Proposed MMN architecture (layers)

1. **MMN node (MMN-box):** router (AP) + Linux computer (Debian/Armbian or OpenWrt), second WiFi card for mesh, optional LoRa module (Meshtastic/MeshCore/RNode) and a radio via an audio interface.
2. **Mesh layer:** 802.11s or B.A.T.M.A.N. adv (local) + Babel/Yggdrasil (between islands).
3. **Addressing and security:** each node has an Ed25519 key; address = key hash (like Reticulum/Yggdrasil).
4. **Services:** messaging (LXMF / local Matrix), node map, community DNS, offline map tiles, offline Wikipedia (Kiwix).
5. **Gateways:** Meshtastic, MeshCore, APRS, SMS (GSM modem, Gammu), FM/CB/DMR radio (DVSwitch, Direwolf), internet, messengers (Matrix + bridges).
6. **Client app:** the phone joins `MMN-xxxx` and opens a local portal with chat, map and status.

## 6. Blockchain and monetisation

### Binding the token to hardware

| Method | Security | Notes |
|---|---|---|
| MAC address | **weak** | trivially changed in software |
| CPU serial / SD card ID | weak | can be faked in software |
| **Key in a secure element** (TPM 2.0, ATECC608, Secure Element, OP-TEE) | **strong** | private key never leaves the chip; the node signs its reports. Needs hardware with such a chip (an ATECC608 module for a Pi costs a few euros) |
| Certificate issued at onboarding | medium–strong | like Helium: hardware "registered" by a trusted maker or volunteer |
| **Proof from neighbours** (witnesses) | strong if done well | nodes confirm they hear each other and forwarded traffic; must resist collusion (Sybil) |

Key point: **reward real, verified work** (data relayed, uptime, coverage confirmed by others), not the mere existence of hardware. Helium rewarded "coverage" and that led to fraud.

### Monetisation ideas

| Model | How it works | Pros | Cons |
|---|---|---|---|
| **Relay credits (proof of relay)** | node collects signed receipts for forwarded packets and redeems them for points/tokens | fair, rewards real service | technically complex |
| **Micropayments like Althea / Lightning** | users pay a neighbour for internet uplink in sats or a stablecoin | no own token needed | payment regulation |
| **Paid gateways** | SMS, internet, satellite cost money; the fee is split among node operators on the path | real revenue | needs paying customers |
| **Selling ready MMN-boxes** | router + computer + antenna + software kit | simple business | thin hardware margins |
| **Services for municipalities, emergency services, companies** | emergency network for a town, fire brigade, festivals, building sites | real money, grants | B2B sales, tenders |
| **Grants** | NLnet/NGI (EU), Mozilla, EU and national digital programmes | ideal for open source | does not scale forever |
| **Own token** | points for node work, token on an exchange | marketing, capital | **MiCA in the EU** (white paper, issuer liability), risk of being a security, speculation, bad press, deters the open-source community |

**My proposal:** start with **points (credits) without an exchange**, computed from signed proofs of relay and redeemable for network services (SMS gateway, satellite, priority). Move to an on-chain token only once there is real traffic and a MiCA lawyer. That gives everyone a measurable benefit without pyramid risk.

## 7. My opinion: pros and cons

### Pros

- **Real need:** the war in Ukraine, floods and blackouts showed how fragile the internet and GSM are.
- **All building blocks exist** as open source, so an MVP is feasible within months.
- **Huge hardware base:** millions of old routers in drawers.
- **Growing Meshtastic/MeshCore communities** looking for "the next step".
- **EU grants** (NGI, NLnet) fund exactly this kind of project.
- **Unique position:** an integrator with "one installer" instead of yet another protocol.

### Cons and risks

- **Physics:** WiFi range is short and mesh throughput drops with each hop. A global network without the internet will be slow and patchy. This must be communicated honestly.
- **Law:** amateur bands forbid encryption and commercial use, so amateur-radio gateways cannot be part of a paid service. CB and PMR have limits too (check with the regulator). Open hotspots with internet access carry operator liability. A token falls under MiCA.
- **Security:** an open network attracts spam, abuse and attacks. Needs rate limits, reputation, encryption.
- **Old routers:** many models, no updates, security holes, high power draw. Without a common firmware, maintenance is a nightmare.
- **Token:** pyramid risk and bad press (especially with the name MMM), fraud in proofs of work, alienating the open-source community.
- **Competition for attention:** Meshtastic is "good enough" for many people.

**Overall:** the idea is valuable if MMN is an **integration layer** (installer + gateways + map + incentives) over existing open projects, with an honest message: "a local, outage-resistant network, linked to others wherever possible". The weakest parts are the promise of "a global network without the internet from millions of routers" and a token at launch. Start with **one city**, an emergency network with gateways, and only then the economics.

## 8. Questions for you (ordered by priority)

1. **Who is the first user?** Residents of one city, a municipality and emergency services, festivals, radio amateurs, or the Meshtastic community? This defines the MVP.
2. **Where do we start geographically?** Which city or region in Poland for a pilot (10–50 nodes)?
3. **Most important service at launch:** text messaging, internet access, voice, or an SMS gateway?
4. **Reference hardware:** do you accept one recommended kit (e.g. an OpenWrt router or Pi + USB card) instead of "any router"?
5. **Legal model:** foundation/association (grants, trust), company (investors, token), or both (foundation + service company like Guifi)?
6. **Token:** can we start with points without an exchange and defer the token until there is real traffic?
7. **Code licence:** fully open (GPL/AGPL) or partly closed?
8. **Budget and time:** how much can you invest in the first 6–12 months, and how many people are on the team?
9. **Who writes the code?** Do you have developers (Linux, networking, embedded), or do we recruit from the community?
10. **Amateur radio and CB:** radio gateways from day one, or in phase two (licences, law)?
11. **Encryption and moderation:** fully anonymous network or accounts and reputation?
12. **Brand:** do you accept **MMN** as the short name? Shall we check the "MishMash" trademark?
